Executable rules

Each rule reads as IF premises, WHEN its guards hold, THEN conclusions, UNLESS an exception applies. Arguments are concepts of the ontology; formulas keep their variable bindings.

How a rule is stored in the database

One row in table rules (id, subject, grade, rule_type, status, optional formula, support label, strict_executable flag) plus ordered atoms in rule_premises, rule_guards, rule_conclusions and rule_exceptions. Each atom is (predicate, args, text, negated); args are concept ids. A rule is strict_executable = 1 only if it is supported, explicit, has premises and conclusions and no suspected missing guard.

Atom texts, formulas and variable descriptions are shown only if they pass the verbatim check (at most 25 words, no run of 8 words shared with the evidence spans); otherwise only the stored structure and ids are shown.
